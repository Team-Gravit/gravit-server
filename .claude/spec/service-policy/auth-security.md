# Auth / Security

- 로그인은 소셜 로그인(Google, Kakao, Naver, Apple)만 지원한다. 자체 계정 가입은 없다. Apple 로그인은 웹과 iOS 앱에서 지원한다
- 소셜 로그인은 제공자가 발급한 토큰을 서버가 제공자에게 확인한 뒤에만 성립한다. 클라이언트가 보낸 사용자 정보를 그대로 신뢰하지 않는다
- 안드로이드 로그인은 Google, Kakao는 id_token을, Naver는 액세스 토큰을 서버에 전달한다
- Apple 웹 로그인은 클라이언트가 받은 인가 코드를 서버가 Apple에 직접 교환하고, Apple이 서명한 id_token의 발급자와 대상이 Gravit 웹인지 확인한 뒤에만 성립한다. 이메일이 없으면 로그인을 거부한다
- Apple iOS 로그인은 앱의 네이티브 모듈이 받은 인가 코드를 서버가 Apple에 직접 교환하고, id_token의 발급자와 대상이 Gravit iOS 앱인지 확인한 뒤에만 성립한다. 앱이 받은 identityToken이나 nonce는 받지 않는다. 이메일이 없으면 로그인을 거부한다
- 웹과 iOS 앱의 Apple 로그인은 같은 Apple 계정이면 같은 사용자로 이어진다
- 소셜 계정 식별자는 `{제공자}_{제공자측 식별자}` 형태로 만들고, 이 값이 같으면 같은 사용자로 본다
- 처음 로그인하는 계정은 그 자리에서 회원가입되고, 닉네임은 소셜 계정 이름, 프로필 이미지는 1번으로 시작한다
- Apple은 검증 가능한 이름을 주지 않으므로 Apple 계정의 첫 닉네임은 `애플사용자`로 시작한다. 닉네임은 온보딩에서 정한다
- Apple 로그인 때 Apple이 발급한 연결 토큰을 암호화해 보관하고, 로그인할 때마다 최신 값으로 바꾼다. 어느 클라이언트(웹, iOS)에서 발급했는지 함께 보관하며, 마지막으로 로그인한 클라이언트 기준으로 바뀐다. 이 토큰은 탈퇴 시 Apple 연결을 해제하는 데만 쓴다(`user.md`)
- 탈퇴 상태 계정의 로그인 처리는 `user.md`를 따른다
- 어드민 화이트리스트에 이메일이 등록되어 있으면 가입 시점에 어드민으로 만들고, 이미 가입한 사용자는 로그인 시점에 어드민으로 승격한다. 승격만 있고 자동 강등은 없다
- 액세스 토큰은 2시간, 리프레시 토큰은 14일 뒤 만료된다
- 웹, 안드로이드, iOS에 동시에 로그인할 수 있다. 같은 종류 기기에서 다시 로그인하면 그 종류의 이전 로그인은 끊긴다
- 웹 로그인은 서버가 발급한 state가 일치해야 성립하며 state는 10분 뒤 만료되고 한 번만 쓸 수 있다. 앱 로그인(안드로이드, iOS)은 state를 쓰지 않는다
- 웹 로그인의 redirect 호스트는 요청의 Origin으로 판별하고, Origin이 등록된 웹 호스트가 아니면 dest로 판별한다. 둘 다 판별되지 않으면 로그인을 거부한다
- 웹 로그인은 리프레시 토큰을 HttpOnly 쿠키로 발급하고 응답 본문에는 담지 않는다. 앱 로그인은 지금처럼 응답 본문으로 발급한다
- 재발급과 로그아웃은 리프레시 토큰 쿠키가 있으면 쿠키를, 없으면 요청 본문의 값을 쓴다
- 로그아웃하면 리프레시 토큰이 무효화되고 쿠키가 지워진다. 로그아웃은 인증 없이 호출할 수 있고, 토큰이 없거나 유효하지 않아도 쿠키는 지운다. 저장된 값과 다른 토큰으로는 현재 세션을 무효화하지 못한다
- 로그아웃은 그 기기 종류의 로그인만 끊고 다른 종류의 로그인은 유지한다
- 탈퇴를 확정하면 그 계정의 모든 로그인이 끊긴다. 복구해도 탈퇴 전 로그인은 되살아나지 않는다
