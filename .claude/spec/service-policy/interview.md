# Interview

면접 도메인의 목적은 CS와 직군 개념을 말로 설명하는 능력을 훈련하는 것이다. 채점은 제출된 텍스트만 대상으로 하고, 약점으로 판정된 문항은 학습 콘텐츠(유닛)로 이어진다.

## 모드

- 세션은 공통 CS(COMMON_CS)와 직군(JOB_SPECIFIC) 두 모드 중 하나로 만든다. 두 모드는 섞이지 않는다. 직군 모드에 CS 문항을 함께 편성하지 않는다
- 공통 CS 모드는 CS 종류 주제를 1~5개 고른다. 스택을 주면 거부한다
- 직군 모드는 직군 그룹에서 스택을 정확히 1개 고른다. 주제 목록을 주면 거부한다
- 공통 CS 모드에서 주제가 0개이거나 6개 이상이면 거부한다. 같은 주제를 두 번 주면 거부한다
- 노출되지 않은 주제, 스택을 주면 거부한다. 노출 규칙은 미결 과제(P8)다

## 주제 태그

주제 태그는 선택과 출제의 단위다. 23개이며 종류(kind)로 CS, 직군 공통, 언어, 프레임워크로 나뉜다.

| 종류 | 태그 (값 - 표시명) |
|------|------|
| CS (5) | DATA_STRUCTURE 자료구조, ALGORITHM 알고리즘, DATABASE 데이터베이스, OPERATING_SYSTEM 운영체제, NETWORK 네트워크 |
| COMMON (4) | SERVER_COMMON 서버 공통, WEB_COMMON 웹 공통, AOS_COMMON 안드로이드 공통, IOS_COMMON iOS 공통 |
| LANGUAGE (6) | JAVA Java, KOTLIN Kotlin, NODE_JS Node.js, PYTHON Python, TYPESCRIPT TypeScript, SWIFT Swift |
| FRAMEWORK (8) | SPRING_BOOT Spring Boot, NEST_JS NestJS, DJANGO Django, REACT React, VUE Vue.js, NEXT_JS Next.js, COMPOSE Compose, SWIFTUI SwiftUI |

- 공통 CS 모드에서 고를 수 있는 태그는 CS 종류뿐이다. 나머지 종류는 스택을 통해서만 출제된다
- 태그에는 직군 그룹이 붙지 않는다. KOTLIN처럼 한 태그가 서버와 AOS 양쪽 스택에 쓰이기 때문이다
- 직군 공통 태그는 그룹마다 하나씩 있다. 네 그룹에 같은 배분 규칙을 적용하기 위해서다

| 그룹 (표시명) | 스택 (값 - 표시명) | 공통 | 언어 | 프레임워크 | 노출 순서 |

| SERVER | NODE_NEST Node.js + NestJS | SERVER_COMMON | NODE_JS | NEST_JS | 3 |

- 스택 목록은 그룹별로 노출 순서 오름차순으로 나간다
- 여러 스택이 공유하는 태그(SERVER_COMMON, SPRING_BOOT, KOTLIN, TYPESCRIPT)의 문제와 학습 콘텐츠는 한 번만 만들면 모든 스택에서 쓰인다

## 난이도

- 난이도는 EASY(하), NORMAL(중), HARD(상) 세 단계다
- 세션을 시작할 때 한 번 고르고, 5문항 모두 그 난이도의 문제만 출제한다. 세션 난이도와 문항 난이도는 같은 값이다

## 입력 방식

- 입력 방식은 TEXT(텍스트)와 VOICE(음성) 중 하나를 세션 시작 시 고른다. 세션 안에서 바꿀 수 없고 섞지 않는다
- 음성 세션은 음성을 텍스트로 변환한 결과를 사용자가 확인, 수정한 뒤 제출한다. 문항당 발화는 1회이고 재녹음은 없다. 발화 시간은 2분이며 2분 동안 말이 없으면 빈 답변으로 제출된다
- 채점은 제출된 텍스트만 대상으로 한다. 음성 원본과 발화 속도 같은 음성 특성은 채점하지 않는다
- 음성 원본은 문항별로 업로드되어 제출 시 답안에 연결되며 계속 보관한다. 세션 안(제출 전 점검)과 리포트 안(복기)에서 재생한다
- 음성 모드의 실제 지원 시점, 변환 엔진, 보관 기간과 정리 방식은 미결 과제(P11)다

## 세션 생성

- 진행 중인 세션이 있어도 새 세션을 만들 수 있다. 중복 생성 차단과 이어하기는 미결 과제(P1)다
- 시도 차수는 사용자의 세션 생성 순서다. 취소된 세션과 채점 실패 세션도 차수를 소비한다
- 세션은 생성 시 만점 스냅샷을 가진다. 문항 배점(정확도 14, 구조성 3, 명료성 3)에 5를 곱한 정확도 70, 구조성 15, 명료성 15다. 이후 배점이 바뀌어도 이미 만든 세션의 만점은 바뀌지 않는다
- 세션 생성과 함께 5문항이 확정되고 답안 5건이 미제출(PENDING) 상태로 만들어진다. 출제된 문제는 이후 바뀌지 않는다
- 세션의 주제는 공통 CS 모드는 고른 주제 1~5개, 직군 모드는 스택 구성 태그 3개로 기록한다
- 출제 배분을 채울 만큼의 활성 문제가 선택한 난이도에 없으면 세션을 만들지 않고 실패를 알린다. 태그 하나라도 부족하면 실패이며, 다른 난이도나 인접 태그로 대체하지 않는다

## 출제

- 선별 단위는 태그다. 활성 상태이고 난이도가 세션 난이도와 같은 문제 중에서만 고른다
- 공통 CS 모드는 고른 주제 수에 따라 5문항을 나눈다

| 주제 수 | 배분 |
|------|------|
| 1개 | 5 |
| 2개 | 3, 2 (3문항을 받을 주제는 랜덤) |
| 3개 | 2, 2, 1 (2문항을 받을 주제 둘은 랜덤) |
| 4개 | 2, 1, 1, 1 (2문항을 받을 주제는 랜덤) |
| 5개 | 1, 1, 1, 1, 1 |

- 직군 모드는 직군 공통 1, 언어 2, 프레임워크 2로 고정이다
- 같은 문제는 한 세션 안에서 다시 출제하지 않는다
- 문항 순서는 공통 CS 모드는 랜덤, 직군 모드는 직군 공통 → 언어 → 프레임워크 순서다
- 같은 사용자의 과거 세션에 나온 문제를 제외하는 규칙은 없다. 재출제 회피는 미결 과제(P4)다

## 답변 제출

- 답변은 5문항을 한 번에 제출한다. 문항별 개별 제출은 없다
- 제출은 세션이 진행 중(IN_PROGRESS)이고 답안 5건이 모두 미제출(PENDING)일 때만 받는다. 그 외에는 거부한다. 따라서 한 세션은 한 번만 제출할 수 있고 재제출은 없다
- 제출 본문은 문항 번호 1~5를 각각 정확히 한 번 포함해야 한다
- 답안 상태는 제출된 내용으로 정해진다. 내용이 없거나 공백이면 무응답(NO_RESPONSE), 그렇지 않으면 답변함(ANSWERED)이다. 제출된 답안 텍스트는 이후 바뀌지 않는다
- 텍스트 세션의 음성 키는 항상 비어 있어야 한다. 값이 있으면 거부한다
- 음성 세션의 음성 키는 서버가 발급한 형식이어야 하며 발급된 세션과 문항에 일치해야 한다. 일치하지 않으면 거부한다. 무응답 문항의 음성 키는 비어 있을 수 있다
- 제출이 받아들여지면 종료 시각을 기록하고 세션은 채점 중(GRADING)이 되며 채점 시도 횟수가 1이 된다. 이후 사용자는 답변을 고칠 수 없다

## 취소

- 취소는 사용자의 명시적 요청으로만 일어난다. 시스템이 자동으로 취소하지 않는다
- 진행 중(IN_PROGRESS) 세션만 취소할 수 있다. 제출 이후에는 취소할 수 없다
- 취소하면 종료 시각을 기록하고 세션은 취소(ABANDONED)가 된다. 취소된 세션은 채점하지 않고 결과와 통계에 포함하지 않는다
- 취소하지 않고 이탈한 세션은 진행 중으로 남는다. 답변은 일괄 제출이므로 제출 전 이탈하면 답변은 서버에 남지 않는다. 회수 정책은 미결 과제(P1)다

## 세션 상태

| 상태 | 의미 | 진입 조건 | 나가는 전이 |
|------|------|------|------|
| IN_PROGRESS | 진행 중 | 세션 생성 | 제출 → GRADING, 취소 → ABANDONED |
| GRADING | 채점 중 | 일괄 제출 성공, 종료 시각 기록, 채점 시도 1회 | 저장 성공 → COMPLETED, 채점 실패 → GRADING_FAILED |
| GRADING_FAILED | 채점 실패 | 문항 채점 1건 이상 실패, 피드백 미저장 | 없음. 복구는 미결 과제(P2) |
| COMPLETED | 완료 | 피드백 5건과 세션 점수가 함께 저장됨 | 없음. 이후 불변 |
| ABANDONED | 취소 | 사용자 명시 요청, IN_PROGRESS에서만 | 없음 |

```
IN_PROGRESS --제출--> GRADING --성공--> COMPLETED
     |                   |
     | 취소           실패 |
     v                   v
 ABANDONED         GRADING_FAILED
```

## 채점

- 채점은 제출이 받아들여진 뒤 자동으로 시작한다. 사용자의 추가 요청은 필요 없다
- 답변함(ANSWERED) 답안만 AI 판정을 받는다. 무응답 답안은 AI를 호출하지 않는다
- 채점 입력은 문제, 모범답안, 핵심 개념 목록, 제출된 텍스트다
- AI는 판정만 한다: 전달한 필수 개념, 전달한 보조 개념, 잘못된 개념 수, 관계없는 발화 수, 질문 이탈 여부, 구조성 단계
- 점수는 판정을 입력으로 고정된 규칙으로 계산한다. AI가 점수를 직접 매기지 않으며 같은 판정은 항상 같은 점수가 된다
- 개선 제안 문장은 판정과 같은 호출에서 함께 만든다. 판정과 설명이 어긋나지 않게 하기 위해서다

| 구조성 | 기준 |
|------|------|
| 3 | 핵심 결론을 먼저 말한 뒤 부연 |
| 2 | 부연이 앞서지만 결론에는 도달 |
| 1 | 결론이 불명확, 나열식 |
| 0 | 무응답 |

| 명료성 | 기준 |
|------|------|
| 3 | 질문에 답하는 내용만, 군더더기 없음 |
| 2 | 관계없는 설명 1개 |
| 1 | 관계없는 설명 2개 이상, 또는 질문에서 벗어남 |
| 0 | 무응답 |

- 잘못된 개념은 정확도에서만, 관계없는 발화는 명료성에서만 깎는다. 같은 발화를 두 번 감점하지 않는다
- 질문 이탈은 관계없는 발화 수와 무관하게 명료성 1점이다. 이탈 여부 자체는 저장하지 않는다(P5)
- 문항마다 정확도, 구조성, 명료성 점수, 정확도 기본 비율, 감점 배율, 관계없는 발화 수, 개선 제안 1건을 저장한다
- 개념별 전달과 누락 판정, 잘못된 개념의 인용과 교정 문장은 저장하지 않는다(P6)
- 피드백 5건과 세션 점수는 함께 확정된다. 부분 점수를 노출하지 않는다

## 점수 계산

문항당 20점, 세션 총점 100점이다. 정확도가 전달력에 우선한다.

**문항 정확도 (만점 14)**

| 항 | 정의 |
|------|------|
| A. 커버리지 | 8 x (전달한 필수 개념 수 / 필수 개념 수). 필수 개념은 모두 같은 비중이다 |
| B. 보조 가산 | 전달한 보조 개념 1개당 +1, 최대 +2 |
| 기본 비율 | min(A+B, 8) / 8. 보조 개념으로 필수 누락을 메울 수 없다 |
| C. 감점 배율 | 잘못된 개념 0개 x1.0, 1개 x0.5, 2개 이상 x0.2 |

- 정확도 = 기본 비율 x 감점 배율 x 14, 반올림. 필수 개념을 모두 말해도 잘못된 개념이 있으면 점수가 내려간다

**문항 전달력 (만점 6)** = 구조성(3) + 명료성(3)

**문항 총점 (만점 20)** = 정확도 + 전달력

**세션 점수**

| 항목 | 계산 | 만점 |
|------|------|------|
| 세션 정확도 | 5문항 정확도 합 | 정확도 만점 스냅샷(70) |
| 세션 전달력 | 5문항 구조성 합 + 명료성 합 | 구조성 만점 + 명료성 만점 스냅샷(30) |
| 세션 점수 | 세션 정확도 + 세션 전달력 | 세션 만점(100) |

- 만점은 항상 세션의 스냅샷 값을 쓴다. 문항 만점은 세션 만점 / 5다

## 무응답

- 제출된 내용이 없거나 공백인 문항은 무응답이다. 음성 세션의 침묵 타이머 만료도 빈 내용 제출로 표현된다
- 무응답 문항은 AI를 호출하지 않는다
- 정확도, 구조성, 명료성은 모두 0점이다. 기본 비율, 감점 배율, 관계없는 발화 수, 개선 제안은 비어 있다
- 5문항 모두 무응답이어도 제출은 유효하며 세션은 완료(COMPLETED)가 된다

## 채점 실패

- 5문항 중 하나라도 채점에 실패하면 어떤 문항의 피드백도 저장하지 않고 세션만 채점 실패(GRADING_FAILED)로 바꾼다. 부분 저장은 없다
- 채점 실패 세션은 결과와 통계에 포함하지 않으며 사용자에게는 상태만 노출한다
- 자동 재시도, 재시도 상한, 재채점은 미결 과제(P2)다

## 결과 노출

- 점수, 피드백, 통계는 완료(COMPLETED) 세션만 대상으로 한다. 진행 중, 채점 중, 채점 실패, 취소 세션은 상태와 문제 목록만 조회할 수 있다
- 완료되지 않은 세션의 종합, 문항별 상세 조회는 거부한다(채점 미완료 오류). 다른 사용자의 세션은 접근 거부다
- 리포트는 저장된 값만 보여준다. 조회 시점에 다시 추론하지 않는다
- 응시 이력은 완료 세션만 포함하며 최신순 또는 오래된 순으로 정렬한다. 페이지당 10건이다. 정렬 기준은 시작 시각이다. 세션의 주제 목록은 태그 선언 순(CS, 직군 공통, 언어, 프레임워크)으로 나간다
- 세션 종합은 총점과 만점, 정확도와 전달력, 전체 평균 정확도와 전달력, 이 세션을 포함한 최근 완료 세션 5개의 추이(오래된 순), 문항별 점수(주제 표시명 기준), 약점 분야를 보여준다. 전체 평균은 서비스 전체 사용자의 완료 세션 평균이다. 최근 5개는 조회 중인 세션의 시작 시각 이전(포함)에 시작한 완료 세션이다
- 문항별 상세는 질문, 주제, 사용자 답변(음성 세션은 음성 키 포함), 모범답안, 핵심 개념 목록, 점수 분해(정확도 14, 구조성 3, 명료성 3)와 개선 제안을 보여준다. 핵심 개념 목록에는 개념별 전달 여부가 없다(P6). 무응답 문항은 답변과 개선 제안이 비어 있고 세 점수가 0이다
- 면접 메인 화면은 완료 세션 수, 최근 완료 세션 5개의 세션 점수 평균, 약점 주제 하위 3개, 최근 세션 3개, 점수 추이(최근 5개, 오래된 순)를 보여준다
- 약점 주제 전체 조회는 주제별 정확도율 오름차순 전체 목록이다
- 평균 점수(전체 평균 정확도와 전달력, 최근 5개 총점 평균)는 정수로 반올림하고, 정확도율은 소수점 첫째 자리까지 반올림한다

## 약점 판정

- 세션 리포트의 약점 분야는 문항 단위로 판정한다. 문항 획득 점수(정확도 + 구조성 + 명료성)가 문항 만점의 절반 이하인 문항의 유닛이며, 중복을 제거한다. 유닛과 함께 문항의 주제 태그를 보여준다
- 문항 단위로 판정하는 이유는 세션당 태그별 문항이 1~5개라 태그 평균의 신뢰도가 낮고, 문항 하나가 유닛 하나를 다루기 때문이다. 절반 이하를 기준으로 삼는 이유는 필수 개념을 절반 이상 놓친 상태를 설명할 수 없는 개념으로 보기 때문이다
- 면접 메인과 약점 주제 전체 조회의 약점 주제는 주제 태그 단위다. 완료 세션의 문항을 주제별로 모아 정확도율(0~100)을 계산하고 오름차순으로 정렬한다. 정확도율은 주제별 문항의 정확도 점수 합을 문항 정확도 만점 합으로 나눈 값이며 무응답 문항은 0점으로 포함한다. 정확도율이 같으면 태그 선언 순이다. 통계이며 학습 이동 대상이 아니다. 학습 이동은 항상 유닛으로 한다
- 약점 판정은 완료 세션의 결과만 쓴다. 채점 실패, 취소, 진행 중 세션은 포함하지 않는다

## 문제 콘텐츠 관리

- 문제는 주제 태그 1개, 유닛 1개, 난이도, 문제 본문, 모범답안, 핵심 개념(필수, 보조)을 갖추어야 등록할 수 있다. 유닛이 없는 문제는 등록할 수 없다
- 핵심 개념은 AI가 전달 여부를 판정할 수 있는 문장 형태로 쓴다. 나쁜 예: `시간복잡도`. 좋은 예: `평균 시간복잡도가 O(n log n)임을 언급`
- 등록된 문제는 수정하지 않는다. 고칠 때는 비활성화하고 새로 등록한다. 미출제 문제의 인플레이스 수정은 미결 과제(P7)다
- 비활성화된 문제는 새로 출제되지 않지만 이미 출제된 세션의 답안과 결과는 그대로 유지된다. 출제된 문제는 삭제하지 않는다
- 태그별 활성 문제 수가 출제 배분에 미치지 못하면 그 태그를 포함하는 주제와 스택은 해당 난이도에서 세션을 만들 수 없다

**콘텐츠 하한**

배분이 고정이고 대체가 없으므로 태그별 하한은 곧 배분 몫이다.

| 태그 종류 | 태그 수 | 난이도당 태그별 하한 | 난이도당 합 |
|------|------|------|------|
| CS | 5 | 5 | 25 |
| COMMON | 4 | 1 | 4 |
| LANGUAGE | 6 | 2 | 12 |
| FRAMEWORK | 8 | 2 | 16 |
| 합계 | 23 | | 57 |

- 세 난이도를 모두 열려면 171문항이 하한이다
- 선택지 노출 규칙은 미결 과제(P8)다. 사용자는 주제나 스택을 먼저 고르고 난이도를 뒤에 고르므로, 방향은 CS 주제는 세 난이도 중 하나라도 하한을 채운 주제만, 스택은 세 난이도 중 하나라도 구성 태그 셋이 모두 하한을 채운 스택만 노출하고, 난이도 선택 단계에서 부족한 난이도를 다시 막는 것이다

## 학습 콘텐츠 연결

- 문제 하나는 주제 태그 하나와 유닛 하나를 가진다. 태그는 출제 필터이고, 유닛은 문제가 다루는 세부 학습 단위이자 약점일 때 이동하는 목적지다
- 면접 도메인은 학습 콘텐츠를 만들지 않고 참조만 한다. 챕터와 유닛의 구조는 `content.md`를 따른다
- 태그는 학습 콘텐츠의 챕터 수준이고 유닛은 그 챕터 안의 한 단위다. 태그 하나에 유닛이 여럿 딸려 있고 문제는 그중 하나를 가리킨다
- 약점 문항의 유닛으로 학습 화면에 이동한다. 연결 경로는 완료 세션 → 문항 획득 점수가 문항 만점의 절반 이하인 문항 → 그 문항의 유닛 → 중복 제거 → 학습 화면이다
- 공통 CS 주제는 기존 학습 콘텐츠의 챕터와 유닛을 그대로 쓴다
- 직군 면접 오픈은 직군 학습 콘텐츠 제작에 종속된다. 직군 공통 4개 챕터가 없으면 해당 스택은 열 수 없다
- 결과 화면에 보여줄 유닛 표시명 규칙은 미결 과제(P9)다
