# Admin / Report

- 어드민 기능은 어드민 권한 계정만 쓸 수 있다. 권한 부여 방식은 `auth-security.md`를 따른다
- 어드민 사용자 관리는 탈퇴한 사용자도 조회하고 상태와 권한을 바꿀 수 있다. 탈퇴한 사용자를 활성이나 정지 상태로 바꾸면 탈퇴가 풀리고 핸들이 새로 발급된다
- 어드민 목록 조회는 페이지 번호가 1부터 시작하고 한 페이지에 20건이다
- 대시보드는 일별 DAU와 월별 MAU 추이를 제공한다. DAU는 그날 활성 이력이 있는 사용자 수, MAU는 그 달력 월에 활성 이력이 있는 사용자 수이며 한 사용자는 한 달에 한 번만 센다. 활성 기준과 이력 보존은 `user.md`를 따른다
- 진행 중인 달의 MAU는 월초부터 조회 시점까지의 값이며 진행 중임을 함께 표시한다. 배포 당일과 배포 월의 수치는 부분 집계다
- 활동이 없는 날과 달은 0으로 채워 요청 구간 전체를 연속으로 준다. 일별은 최대 365일, 월별은 최대 36개월까지 조회할 수 있고 범위를 벗어나면 실패한다
- 문제 신고는 존재하는 문제에만 할 수 있다
- 사용자 신고는 로그인한 사용자가 다른 활성 사용자에 대해 할 수 있다. 정지된 사용자도 활성 사용자로 본다. 탈퇴한 사용자와 자기 자신은 신고할 수 없다
- 사용자 신고 사유는 부적절한 닉네임과 기타 두 가지다. 상세 내용은 선택이고 500자 이하다
- 같은 대상에 처리되지 않은 내 신고가 있으면 다시 신고할 수 없다. 그 신고가 처리된 뒤에는 다시 신고할 수 있다
- 사용자 신고에는 신고 시점의 닉네임이 함께 남는다. 대상이 나중에 닉네임을 바꿔도 무엇이 신고됐는지 확인할 수 있다
- 어드민은 사용자 신고 목록을 사유와 처리 여부로 걸러 볼 수 있고, 처리 여부를 바꿀 수 있다. 처리되지 않은 상태로 되돌릴 때 같은 신고자와 대상의 처리되지 않은 신고가 이미 있으면 실패한다
- 어드민은 사용자의 닉네임을 기본 닉네임(`유저` + 숫자 6자리)으로 초기화할 수 있다. 초기화하면 그 사용자에게 걸린 처리되지 않은 부적절한 닉네임 신고가 모두 처리 완료가 되고, 감사 로그에 이전과 이후 닉네임이 남는다. 기타 사유 신고는 자동으로 처리하지 않는다
- 닉네임이 초기화된 사용자에게 알림은 보내지 않는다
- 학습 콘텐츠는 스테이징에서 만들고 검수한 뒤 운영으로 승격한다. 승격 전에는 사용자에게 보이지 않는다
- 스테이징 콘텐츠는 외부 생성기가 적재한다
- 승격 검수 기준은 레슨당 문제 6개(객관식 4개, 주관식 2개)이고, 객관식 문제는 선택지가 4개여야 한다. 기준에 맞지 않으면 승격되지 않는다. 선택지나 정답이 같은 라벨의 문제를 가리키지 않아도 승격되지 않는다
- 이미 승격된 라벨은 다시 승격할 수 없다
- 승격해도 스테이징 원본은 지우지 않고 남긴다. 승격은 감사 로그에 기록된다
- 새 콘텐츠 알림은 종류만 정의되어 있고 레슨 승격과 아직 연결되어 있지 않다. 현재는 QA 경로에서 본인에게 보내는 것만 동작한다
