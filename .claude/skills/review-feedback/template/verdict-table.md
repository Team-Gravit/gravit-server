# 판정 표 템플릿

Phase 4에서 판정 결과를 사용자에게 보고할 때 쓰는 형식이다.

## 사용법

- 행 순서는 상 → 중 → 하다. 같은 판정 안에서는 코드래빗이 남긴 순서를 유지한다
- 판정이 하나도 없는 등급은 행을 만들지 않는다. 등급별 소계는 표 아래 요약 줄에 남긴다
- **대상**: `클래스명:라인` 까지만 쓴다. 파일 경로 전체는 쓰지 않는다. Java가 아닌 파일(마이그레이션 SQL 등)은 파일명만 쓴다
- **지적 요지**: 코드래빗 본문을 그대로 옮기지 말고 한 줄로 줄인다
- **판정 근거**: 왜 그 등급인지를 한 줄로. 확인한 클래스명을 근거에 포함한다
- 처리 이력이 있어 판정에서 뺀 항목은 표에 넣지 말고 요약 줄의 제외 건수로만 센다

## 형식

| # | 판정 | 대상 | 지적 요지 | 판정 근거 |
|---|------|------|-----------|-----------|
| 1 | 상 | `{클래스}:{라인}` | {한 줄 요지} | {한 줄 근거} |
| 2 | 중 | `{클래스}:{라인}` | {한 줄 요지} | {한 줄 근거} |
| 3 | 하 | `{클래스}:{라인}` | {한 줄 요지} | {한 줄 근거} |

상 {a}건 / 중 {b}건 / 하 {c}건, 처리 이력으로 제외 {d}건

수정할 번호를 골라주세요.

## 예시

| # | 판정 | 대상 | 지적 요지 | 판정 근거 |
|---|------|------|-----------|-----------|
| 1 | 상 | `Mission:124` | `targetValue`가 0이면 진행률이 NaN으로 응답에 노출됨 | 생성 시 양수 검증이 없고 `MissionDetailResponse`가 값을 그대로 내려줌 |
| 2 | 중 | `MissionService:82` | 완료 처리에 낙관적 락 부재 | 조건부 UPDATE로 중복 지급은 이미 막히지만 진행도 갱신은 경합 여지가 남음 |
| 3 | 하 | `UserMission:81` | `addProgress`에 음수 방어 필요 | 증가값은 `Mission.calculateLessonIncrement`가 0 이상으로만 만들어 도달 불가 |

상 1건 / 중 1건 / 하 1건, 처리 이력으로 제외 0건

수정할 번호를 골라주세요.
