# [PLAN-580] Apple 웹 로그인 추가

> 이슈: #580
> 브랜치: feat/580-apple-login

## 목표
웹에서 Apple 계정으로 가입, 로그인할 수 있게 한다. 프론트가 Apple JS SDK 팝업으로 받은 `code`를 서버가 Apple과 교환하고, id_token을 검증해 `sub`로 사용자를 식별한다.
탈퇴 시 Apple 연결을 해제(App Store 심사 5.1.1(v))할 수 있도록 Apple refresh_token을 암호화해 보관하고, 탈퇴 확정 시 철회한다. iOS 네이티브 로그인은 범위 밖이다.

## 구현 계획

### 1. Flyway - `V48__add_apple_credential.sql`

```sql
-- V48__add_apple_credential.sql

-- Apple 로그인 사용자의 Apple refresh_token. 탈퇴 시 Apple 연결 해제에 쓰며, AES-GCM 암호문으로 저장한다
CREATE TABLE apple_credential (
    id            BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    user_id       BIGINT       NOT NULL,
    refresh_token TEXT         NOT NULL,
    created_at    TIMESTAMP(6),
    updated_at    TIMESTAMP(6),
    CONSTRAINT uq_apple_credential_user_id UNIQUE (user_id),
    CONSTRAINT fk_apple_credential_user FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);
```
- `user_id` UNIQUE가 조회 인덱스를 겸하므로 별도 인덱스는 두지 않는다.

### 2. Entity - `AppleCredential` (`auth/domain`, `BaseEntity` 상속, `@Table(name = "apple_credential")`)
- 필드: `Long id`, `long userId`(`user_id`, unique), `String refreshToken`(`refresh_token`, `columnDefinition = "TEXT"`, 암호문)
- `static AppleCredential create(long userId, String encryptedRefreshToken)`
- `void updateRefreshToken(String encryptedRefreshToken)`

### 3. Repository - `AppleCredentialRepository extends JpaRepository<AppleCredential, Long>`
- `Optional<AppleCredential> findByUserId(long userId)` - 파생 쿼리
- `void deleteByUserId(long userId)` - `@Modifying` + JPQL `DELETE FROM AppleCredential c WHERE c.userId = :userId`

### 4. 설정, 지원 컴포넌트
- `AppleOAuthProps` - `@ConfigurationProperties(prefix = "oauth.apple")` record: `issuer`, `tokenUri`, `revokeUri`, `jwkSetUri`, `teamId`, `clientId`, `keyId`, `privateKey`, `tokenEncryptionKey`
- `AppleClientSecretGenerator` (`@Component`)
  - 생성자에서 `privateKey`를 `Base64.getMimeDecoder()` → `PKCS8EncodedKeySpec` → `KeyFactory("EC")`로 파싱해 필드에 보관. 실패하면 `RestApiException(APPLE_CONFIG_INVALID)` (기동 실패)
  - `String generate()` - jjwt로 header `kid=keyId`, `iss=teamId`, `sub=clientId`, `aud=issuer`, `iat=now(clock)`, `exp=now+5분`, `Jwts.SIG.ES256` 서명
- `AppleTokenCipher` (`@Component`)
  - 생성자에서 `tokenEncryptionKey`를 Base64 디코딩해 32바이트 AES 키로 보관. 길이가 다르면 `APPLE_CONFIG_INVALID`
  - `String encrypt(String plainText)` - 12바이트 랜덤 IV, `AES/GCM/NoPadding`(태그 128비트), `Base64(iv + 암호문)` 반환
  - `String decrypt(String cipherText)` - 역순. 실패 시 `RestApiException(APPLE_TOKEN_CRYPTO_FAILED)`
- `AppleIdTokenDecoder` (`@Component`, `auth/infrastructure/client`)
  - 생성자에서 `NimbusJwtDecoder.withJwkSetUri(props.jwkSetUri()).build()` (기본 검증기: exp, nbf)
  - `Jwt decode(String idToken)` - 예외를 `RestApiException(FAIL_DECODE_ID_TOKEN_TO_JWT)`로 변환
  - JwtDecoder 빈으로 두지 않는 이유: `OidcConfig`의 google, kakao `JwtDecoder` 빈과 타입이 겹쳐 주입이 모호해진다

### 5. OAuth 클라이언트 포트
- `OAuthClient.revokeToken(String revokeUri, MultiValueMap<String, String> revokeRequest)` 추가
- `OAuthHttpClientAdapter.revokeToken` - form POST, 응답 본문 무시(`toBodilessEntity()`). `RestClientException`은 로그 후 `RestApiException(OAUTH_SERVER_ERROR)`

### 6. DTO
- `AppleUserInfo(Map<String, Object> claims) implements OAuthUserInfo`
  - `getProvider()` → `"apple"`, `getProviderId()` → `sub`, `getEmail()` → `email`
  - `getName()` → 상수 `DEFAULT_NAME = "애플사용자"` (결정 1)
- `AppleLoginDto(OAuthUserInfo userInfo, String refreshToken)` - `dto/internal`, `of(...)`
- 요청 DTO는 기존 `AuthCodeRequest(code)`를 재사용한다

### 7. Service
- `AppleOAuthService` (`auth/service/oauth/apple`)
  - 상수: `PROVIDER = "apple"`, `GRANT_TYPE = "authorization_code"`, `TOKEN_TYPE_HINT = "refresh_token"`, 응답 키 `id_token`, `refresh_token`
  - `AppleLoginDto getUserInfo(String authCode, String dest)`
    1. `authCode` 빈 값 → `AUTH_CODE_INVALID`. `dest` → `RedirectHostConst.DEST_BASE` 조회, 없으면 `DEST_NOT_VALID`
    2. `redirectUri = baseHost + OAuthLoginUrlService.REDIRECT_PATH_PREFIX + PROVIDER`
    3. form(`grant_type`, `client_id`, `client_secret=generator.generate()`, `redirect_uri`, `code`=URL 디코딩)으로 `oAuthClient.getAccessTokenResponse(props.tokenUri(), form)`
    4. 응답에 `id_token`이 없으면 `OAUTH_ID_TOKEN_INVALID`
    5. `appleIdTokenDecoder.decode` → `iss != props.issuer()`이면 `ISSUER_NOT_MATCHING`, `aud`가 비면 `AUDIENCE_IS_EMPTY`, `clientId` 미포함이면 `AUDIENCE_NOT_MATCHING` (`OAuthAndroidUserInfoService`와 같은 방식)
    6. `new AppleUserInfo(claims)` → `OAuthUserInfoValidator.validate` → `AppleLoginDto.of(userInfo, refreshToken)`
  - `void revokeRefreshToken(String refreshToken)` - form(`client_id`, `client_secret`, `token`, `token_type_hint=refresh_token`)으로 `oAuthClient.revokeToken(props.revokeUri(), form)`
- `AppleCredentialService` (`auth/service/oauth/apple`)
  - `@Transactional void save(long userId, String refreshToken)` - 암호화 후 `findByUserId`가 있으면 `updateRefreshToken`, 없으면 저장
  - `@Transactional(readOnly = true) Optional<String> findRefreshToken(long userId)` - 복호화해 반환
  - `@Transactional void deleteByUserId(long userId)`
- `OAuthLoginProcessor`
  - `@Transactional LoginResponse processApple(AppleLoginDto appleLoginDto)` - `findOrCreateUser` → refresh_token이 있으면 `appleCredentialService.save(user.getId(), token)` (같은 트랜잭션, 없으면 warn 로그) → 토큰 발급
  - 기존 `process`와 공통인 토큰 발급부를 `private LoginResponse issueLoginResponse(User user)`로 분리
  - 탈퇴 상태 계정이면 `findOrCreateUser`가 `AccountSoftDeletedException`을 던져 토큰도 저장하지 않는다. 복구 후 다시 로그인할 때 저장된다
- `UserDeletionService.confirmDeleteByMailAuthCode` - `deleteById` 뒤 `publisher.publishEvent(new UserWithdrawnEvent(user.getId()))` (기존 트랜잭션 안)

### 8. Listener - `AppleTokenRevokeListener` (`auth/listener`)
- `@TransactionalEventListener(phase = AFTER_COMMIT) handleUserWithdrawn(UserWithdrawnEvent event)`
  - `appleCredentialService.findRefreshToken(userId)`가 있으면 `appleOAuthService.revokeRefreshToken(token)` → 성공하면 `appleCredentialService.deleteByUserId(userId)`
  - 예외는 잡아서 error 로그만 남긴다. 행이 남아 있으므로 실제 삭제 때 다시 시도된다 (결정 5)

### 9. Facade - `UserDeletionFacade.cleanUserDeletion` (기존 Facade 확장, user + interview + auth 조합)
- 기존 `voiceSessionIds` 수집처럼, 삭제 전에 `appleCredentialService.findRefreshToken(userId)`를 미리 읽는다
- `userDeletionService.cleanUserDeletion`이 `true`면 `revokeAppleToken(token)`(private, 예외를 잡아 error 로그) → 음성 삭제 순으로 진행
- 행 자체는 `UserCleanDeletionSql`의 `d_apple_credential` CTE가 지운다 (철회 성공 여부와 무관)

### 10. Controller - `OAuthController`
- `POST /api/v1/oauth/apple?dest={dest}` body `AuthCodeRequest` → `appleOAuthService.getUserInfo` → `oAuthLoginProcessor.processApple` → `200 LoginResponse`
- 리터럴 경로 `/apple`이 기존 `/{provider}`보다 우선 매칭된다. `Provider` enum에는 apple을 넣지 않는다 (`/login-url/{provider}`가 없는 ClientRegistration을 찾게 됨)
- Facade 불필요 - 두 Service 모두 auth 도메인
- 보안: `/api/v1/oauth/**`는 이미 permitAll, `JwtAuthFilter` 제외 대상

### 11. 정책 문서
- `auth-security.md`: 로그인 지원 목록에 Apple(웹) 추가, Apple은 이름을 확인할 수 없어 첫 닉네임을 `애플사용자`로 시작, Apple 토큰을 탈퇴 시 연결 해제용으로만 암호화 보관
- `user.md`: 탈퇴 확정 시 Apple 연결을 해제하고, 실패하면 실제 삭제 때 다시 시도. 실제 삭제 범위에 Apple 토큰 추가

## Deviation Log
> implement 스킬이 구현 중 계획을 벗어난 지점을 여기에 기록한다. (작성 시점엔 비워둔다)
- `AppleCredentialService.deleteByUserId`: `@Transactional` → `@Transactional(propagation = REQUIRES_NEW)` - 이유: `AFTER_COMMIT` 리스너에서 호출되므로 이미 커밋된 트랜잭션에 참여하면 삭제가 반영되지 않는다 (facade.md 보상 규칙)
- `OAuthController.appleLogin`: 요청 본문에 `@Valid` 추가 - 이유: `AuthCodeRequest.code`의 `@NotNull`이 동작하도록. 기존 `/{provider}`는 손대지 않았다
- `AppleUserInfo`: `PROVIDER`, `DEFAULT_NAME`을 `public static final`로 둠 - 이유: `AppleOAuthService`가 redirect_uri 경로를 만들 때 같은 제공자 이름을 참조
- `AppleClientSecretGenerator.generate`: `aud`를 `audience().single(...)`로 문자열 단일 값으로 넣음 - 이유: Apple 문서의 client_secret 예시가 문자열이다. jjwt의 `add()`는 배열로 직렬화한다
