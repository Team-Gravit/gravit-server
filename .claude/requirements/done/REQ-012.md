# [REQ-012] 문의(Inquiry) API 개발 — 유저 CRUD

> GitHub 이슈 #404 (브랜치 `feat/404-inquiry-api`)

## 개요

유저가 CS 문의를 제출/조회/수정/삭제하고, 어드민이 답변하는 기능. 문의 본문(유저 작성)과 답변(어드민 작성)을 별도 엔티티(`Inquiry`, `InquiryAnswer`)로 분리한다. 이번 REQ 범위는 **유저 CRUD까지**이며, 어드민 답변 작성 API는 후속 이슈로 분리한다.

## API

모든 엔드포인트는 인증 유저의 **본인 문의**로 스코프된다.

| Method | Path | 설명 |
|--------|------|------|
| POST | `/api/v1/inquiries` | 문의 제출 |
| GET | `/api/v1/inquiries` | 본인 문의 목록 조회 (페이징) |
| GET | `/api/v1/inquiries/{id}` | 본인 문의 상세 조회 (답변 nullable 포함) |
| PUT | `/api/v1/inquiries/{id}` | 문의 수정 (`status == PENDING`일 때만) |
| DELETE | `/api/v1/inquiries/{id}` | 문의 삭제 (soft delete) |

## 도메인 모델

`Inquiry`(문의, 유저 작성) ──1:1── `InquiryAnswer`(답변, 어드민 작성).
`inquiry_answer.inquiry_id`에 UNIQUE 제약으로 1:1 보장. 추후 대화 스레드(1:N) 전환이 필요하면 UNIQUE만 제거.

### Inquiry 엔티티
- `id`: Long PK
- `title`: String, blank 불가, 최대 50자
- `type`: `InquiryType` enum
- `content`: TEXT, blank 불가
- `status`: `InquiryStatus` enum, 기본 `PENDING`
- `userId`: long (작성자 — Report 패턴으로 User 조인 회피)
- `createdAt` / `updatedAt`: `BaseEntity` 상속
- `deletedAt`: soft delete (`@SQLDelete` + `@SQLRestriction`)

### InquiryAnswer 엔티티 (이번엔 스키마/엔티티만 생성, 쓰기 API는 후속 이슈)
- `id`: Long PK
- `inquiryId`: long, FK, UNIQUE
- `content`: TEXT
- `adminId`: long (답변 작성 어드민)
- `createdAt` / `updatedAt`: `BaseEntity` 상속

> `Inquiry.status`가 해결 여부의 단일 소스. 어드민 답변 생성 시 `InquiryAnswer` insert + `Inquiry.status = RESOLVED`를 한 트랜잭션으로 처리(후속 이슈).

### Enum
- `InquiryType { BUG_REPORT, CONTENT_ERROR, FEATURE_SUGGESTION, OTHER }`
- `InquiryStatus { PENDING, RESOLVED }`

## 비즈니스 규칙

- 모든 조회/수정/삭제는 `userId == 인증유저` 검증. 남의 문의 접근 시 `INQUIRY_FORBIDDEN` 예외.
- 존재하지 않는(또는 soft delete된) 문의 접근 시 `INQUIRY_NOT_FOUND` 예외.
- 답변이 달려 해결된 문의(`status == RESOLVED`)는 수정/삭제 잠금 → `INQUIRY_ALREADY_RESOLVED` 예외.
- `title`은 blank 불가 + 최대 50자, `content`는 blank 불가 → 위반 시 `INQUIRY_TITLE_INVALID` / `INQUIRY_CONTENT_INVALID`.
- 삭제는 soft delete (`@SQLDelete` + `@SQLRestriction`).
- 상세 응답에는 답변(`InquiryAnswer`)을 nullable로 포함해 프론트 계약을 안정화한다.

## 범위 밖 (후속 이슈)

- 어드민 답변 작성 API (`InquiryAnswer` insert + `status` 전이)
- 어드민 전체 문의 목록/검색, 작성자 닉네임 조인

## DB 마이그레이션

- `V23__add_inquiry.sql` : `inquiry` + `inquiry_answer` 두 테이블 동시 생성 (스키마 미리 확정해 후속 마이그레이션 churn 방지).
- enum 컬럼은 `VARCHAR(255)` + `CHECK`, timestamp는 `TIMESTAMP(6)`, soft delete 컬럼 `deleted_at`.
- `inquiry_answer.inquiry_id`에 UNIQUE + FK 제약.
